## 0. 产品定位与设计原则

### 0.1 定位

产品正式定位为 **AI 录音工作台（AI Recording Workspace）**。

它不是“录音机 + 转写结果页”，而是以录音为起点、以 AI 理解与知识沉淀为终点的工作空间。

### 0.2 核心原则

> 录音是入口，实时转录是基础，AI 理解是核心，知识沉淀是最终价值。

四句话对应四层产品职责，也对应界面的四个优先级：

| 层级 | 产品职责 | 界面承载 |
|---|---|---|
| 入口 | 稳定、低摩擦地开始录音 | 左侧录音控制中心 |
| 基础 | 实时、可读、可定位的转录 | 中间内容工作区的转录视图 |
| 核心 | 主题、观点、决策、任务与问答 | 右侧 AI 洞察 + AI 分析/对话视图 |
| 价值 | 可确认、可检索、可复用的记录 | 录音复盘工作区与知识中心 |

### 0.3 与现有界面的关系

本次**不建议**在原有界面上简单叠加功能，而是重新定义工作台的交互结构，同时保留现有简洁的视觉风格（v7 极光玻璃：极光画布、玻璃主面板、绿/Iris 双语义色）。

现有左右两栏结构可以保留，但右侧需要进一步升级为可承载多视图的内容工作区，并增加独立的 AI 洞察区域。

## 1. 重新定义工作台结构

### 1.1 三个逻辑区域

```text
┌──────────────────────────────────────────────────────────────────────────┐
│  AI Recording Workspace                                                  │
├──────────────────┬───────────────────────────────────┬───────────────────┤
│  左侧控制面板      │  中间内容工作区                     │  右侧 AI 洞察      │
│                  │                                   │                   │
│  录音场景          │  [转录] [翻译] [AI分析] [任务] [对话] │  当前主题          │
│  语音/音频/AI 配置  │                                   │  关键观点          │
│                  │  发言人 01 · 00:03:12              │  决策事项          │
│  录音状态          │  今天主要讨论项目的技术架构……        │  争议与分歧        │
│  计时 / 波形       │                                   │  待办事项          │
│  暂停 / 结束       │  发言人 02 · 00:03:28              │  待确认问题        │
│                  │  我认为需要优先解决稳定性问题……       │                   │
│  双通道电平        │                                   │  来源可点击定位     │
│                  │  正在识别下一段语音……               │                   │
└──────────────────┴───────────────────────────────────┴───────────────────┘
```

| 区域 | 职责 | 操作频率 |
|---|---|---|
| 左侧控制面板 | 录音配置、设备、模型、录音控制与状态 | 低（开始前与录音中少量操作） |
| 中间内容工作区 | 转录、翻译、内容阅读、任务、AI 对话 | 高（录音全程主要阅读区） |
| 右侧 AI 洞察 | 摘要、观点、决策、任务、待确认问题 | 中高（浏览与跳转） |

### 1.2 空间规则

这是本次结构设计最重要的决定：

**录音过程中，不能让 AI 分析区域挤占实时转录的主要阅读空间。**

因此右侧 AI 洞察必须支持：

1. **折叠**：一键收起为窄条或完全隐藏，收起后中间工作区立即扩展。
2. **调整宽度**：在约定范围内拖拽调整，且中间转录区保持可读的最小宽度。
3. **独立展开**：可从洞察项展开详情，但不以模态遮罩覆盖正在阅读的转录内容。

### 1.3 自适应建议（待详细设计锁定）

| 窗口宽度 | 建议布局 |
|---|---|
| ≥ 1440 px | 三栏常驻，AI 洞察默认展开 |
| 1100–1440 px | 三栏，AI 洞察默认收起或半宽 |
| < 1100 px | 保留“控制 + 内容”两栏，AI 洞察改为可呼出的侧滑面板 |
| 最小窗口 960 × 640 px | 不允许控件重叠或整页横向滚动 |

具体断点、各栏宽度与拖拽阈值在 Workspace UI V1.0 详细规格中锁定。实际布局可根据窗口宽度自动调整，AI 洞察也可以折叠。

## 2. 左侧控制面板：从配置表单变成录音控制中心

现有左侧功能排列比较平铺。建议按“场景 → 配置 → 状态与控制”三层重新组织，并让录音状态区成为整个左栏视觉与操作的重心。

### 2.1 录音场景

增加场景预设，场景不是换文案，而是绑定不同的 AI 分析提示词与输出结构。

| 场景 | 说明 | AI 绑定建议 |
|---|---|---|
| 会议 | 多人讨论、纪要 | 决策、待办、负责人、分歧、待确认问题 |
| 学习 | 课程、讲座 | 知识点、概念解释、例题、复习清单 |
| 灵感 | 个人语音记录 | 想法归类、可执行下一步、关联主题 |
| 访谈 | 一对多问答 | 受访者观点、引语、追问建议 |
| 电话记录 | 通话纪要 | 双方诉求、约定事项、时间点 |
| 自由录音 | 不做结构假设 | 通用摘要与关键句 |

场景切换要求：

- 录音开始后不允许切换场景，避免分析上下文错位；可在录音结束后重新分析时选择。
- 每个场景必须定义：默认提示词、输出结构、洞察卡片类型、任务提取策略。
- 场景选择需持久化，下次打开沿用上次选择。

### 2.2 录音配置

配置分为三个可折叠区域，默认只展开最常用的一组，避免配置长期占据主界面。

| 分组 | 包含项 | 默认状态建议 |
|---|---|---|
| 语音配置 | 语言识别、翻译目标语言、字幕开关 | 展开 |
| 音频配置 | 麦克风、系统声音、采样率、音频格式 | 收起 |
| AI 配置 | 模型、API Key、实时分析频率、提示词 | 收起 |

要求：

- **AI 模型和 API Key 不应长期占据主界面空间**，收起后仅以一行摘要展示当前模型与连接状态。
- API Key 只显示掩码与“已配置/未配置”，编辑入口进入独立设置区，不在主面板明文展示。
- 折叠状态持久化；录音中允许修改的项与禁止修改的项必须有明确区分（如语言、模型在录音中变更需二次确认）。
- 未配置或不可用的选项要有可理解的禁用原因，而不是静默失败。

### 2.3 录音状态区域

这是整个左侧最重要的部分。录音开始后，配置区应自动收起，把空间让给状态与波形。

```text
Recording
00:12:35
正在录音 · 本地安全保存

[ 暂停 ]   [ 结束 ]

麦克风输入        正常   ▁▃▅▇▅▃▁
系统声音          正常   ▁▂▄▆▄▂▁
```

要求：

- 计时字号为左栏最大视觉元素，格式 `HH:MM:SS`；不足一小时可显示 `MM:SS`，但跨小时后不得跳动布局。
- 状态文案必须同时表达“录音中/已暂停”和“本地保存状态”，不能只用颜色。
- 暂停/结束为主操作，异步命令执行期间禁用并显示加载态，防止重复提交。
- 双通道电平分别展示麦克风与系统声音，并给出“正常/无声/异常”的文字状态。
- **波形与电平必须使用音频输入的 RMS 或峰值实时计算**，不得使用静态假数据。示意图中的数据只是视觉演示。
- 暂停时波形停止动态并降低饱和度；尊重系统“减少动态效果”设置。
- 设备掉线、静音、系统音频未播放等情况需在状态区就地提示，并提供恢复入口。

## 3. 右侧内容工作区：五种视图

### 3.1 统一 Tab 导航

内容工作区顶部使用统一 Tab 导航，五个视图共享同一份录音上下文，而不是五个互相独立的页面。

| 视图 | 主要内容 | 默认 | 数据来源 |
|---|---|---|---|
| 转录 | 带时间戳、说话人的实时文本 | 默认打开 | ASR / 本地 Whisper |
| 翻译 | 原文与译文对照 | 按需 | 翻译服务 / 本地模型 |
| AI 分析 | 实时主题、关键观点、争议、决策、待确认问题 | 按需 | AI 分析 |
| 任务 | 行动项、负责人、截止时间、来源片段 | 按需 | AI 提取 + 人工确认 |
| AI 对话 | 基于当前录音内容提问，支持引用原始片段 | 按需 | 检索 + LLM |

### 3.2 视图 1：实时转录

- 产品的主要工作区，录音开始后默认展示。
- 每个片段包含：说话人、时间戳、文本、识别状态与独立操作。
- 显示识别置信度（如“识别置信度 96%”）与操作入口：“音频定位 · 编辑 · 复制”。
- 新片段到达时保持阅读位置稳定，具体规则见第 4 节。

### 3.3 视图 2：双语翻译

- 原文与译文上下或左右排列，两者时间戳严格一致。
- 默认跟随转录自动滚动；切换为双语后不得丢失当前阅读位置。
- 译文使用 Iris 语义色标识 AI 能力，原文保持中性色。
- 翻译失败时保留原文，并就地显示“重试/仅看原文”，不得清空已有内容。

### 3.4 视图 3：AI 分析

- 实时呈现主题、关键观点、争议与分歧、决策事项、待确认问题。
- 每条分析必须可回溯到来源片段（时间范围或片段引用）。
- 区分“AI 推断”和“原始事实”，具体规则见第 5 节。
- 分析结果按时间增量更新，不得整块重排导致用户正在阅读的内容跳动。

### 3.5 视图 4：任务

- 展示行动项、负责人、截止时间、来源片段与确认状态。
- 支持确认、编辑、忽略；未确认任务不得进入正式记录或知识库。
- 负责人和截止时间未识别时显示“待确认”，不允许 AI 自行编造。
- 支持按“待确认 / 已确认 / 已完成”筛选。

### 3.6 视图 5：AI 对话

- 基于当前录音内容提问，回答必须带引用，可点击跳转到原始转录片段与对应音频位置。
- 支持追问，对话上下文限定在当前录音内；跨录音问答属于后续知识中心能力。
- 回答中涉及的每个观点、任务、决策都应可溯源，不允许只给结论不给来源。
- 示例：

> 用户：刚才讨论的三个技术问题是什么？
>
> AI：分别是系统稳定性、数据处理效率和 AI 接入成本（00:02:13）。其中优先解决稳定性（00:02:35）。[跳转到片段]

### 3.7 共享上下文与跨视图跳转

五个视图不是五个独立页面，必须共享同一份录音上下文：

- 统一的数据源：同一份转录、翻译、分析、任务与会话状态。
- 任一视图中的引用、时间戳、任务来源均可跳转到对应片段并高亮。
- 切换 Tab 不重置滚动位置、筛选条件与对话历史。
- 视图之间不复制数据，只引用片段 ID 与时间范围。

## 4. 实时转录的交互细节

转录文本不是普通聊天消息，应按音频内容设计。

### 4.1 片段结构

```text
发言人 01                                   已完成
00:03:12
今天我们需要确定下一阶段的技术方案。
[播放音频] [编辑文本] [复制] [标记重点]
```

- 说话人：可点击修改身份或重命名。
- 时间戳：可点击跳转音频。
- 状态：已完成 / 识别中 / 已编辑 / 识别失败。
- 操作：播放、编辑、复制、标记重点；更多操作收纳到菜单。

### 4.2 交互清单

| 交互 | 说明 |
|---|---|
| 点击时间戳 | 跳转音频到对应位置 |
| 双击文本 | 编辑识别结果 |
| 选中文本 | 提供 AI 解释、翻译、总结 |
| 标记重点 | 加入重要内容与复盘区 |
| 选择说话人 | 修改说话人身份 |
| 删除片段 | 记录操作历史，可撤销 |
| 固定片段 | 防止自动滚动时丢失阅读位置 |

### 4.3 自动滚动规则

这是长录音阅读体验的关键：

1. 用户没有手动滚动时，自动跟随最新转录。
2. 用户向上浏览历史时，暂停自动滚动。
3. 暂停跟随期间显示“回到最新内容”按钮，并提示新内容数量。
4. 新内容到达时不得强制改变用户当前阅读位置。
5. 用户回到底部后恢复自动跟随；固定片段不因自动滚动被移出视野。

### 4.4 未完成片段

- “识别中”片段使用轻微动态标识，例如低透明度呼吸或渐变边框，**不应频繁闪烁**。
- 未完成文本不参与复制全文、导出与 AI 总结，避免半句进入正式记录。
- 识别失败片段保留占位与重试入口，不静默丢弃。

### 4.5 编辑与历史

- 编辑保存后标记“已编辑”，原文保留在操作历史中。
- 编辑不得破坏时间戳与音频定位关系；删除片段后时间轴仍可正常回放。
- 所有编辑、删除、标记重点操作进入本地操作历史，支持撤销。

## 5. AI 洞察区域：不要只做摘要

### 5.1 六类洞察

```text
AI 实时洞察
当前主题
AI 开发平台技术架构讨论

关键观点
系统稳定性应该优先于新功能开发。
来源：00:03:12～00:03:28

决策事项
暂定先解决稳定性问题。
待人工确认

争议与分歧
目前尚未检测到明确分歧。

待办事项
制定系统稳定性优化方案。
负责人待确认

待确认问题
稳定性优化的验收指标是什么？
```

以上内容为交互样例，不代表真实 AI 分析结果。

| 类型 | 说明 | 是否可直接成为正式记录 |
|---|---|---|
| 当前主题 | 当前讨论的主题归纳 | 否，需来源 |
| 关键观点 | 重要观点及其来源 | 否，需来源 |
| 决策事项 | 已明确或暂定的决策 | 否，默认“待人工确认” |
| 争议与分歧 | 明确分歧或“尚未检测到” | 否 |
| 待办事项 | 行动项、负责人、截止时间 | 否，需确认 |
| 待确认问题 | 尚未有结论的问题 | 否 |

### 5.2 事实与推断必须区分

AI 推断和原始事实必须在视觉与文案上区分，不能让 AI 把推断当成会议决策。

| 类型 | 定义 | 界面标识 |
|---|---|---|
| 原始事实 | 发言人实际说了什么 | 引用原文 + 时间戳，中性色 |
| AI 总结 | AI 对内容的归纳 | “AI 总结”标签，Iris 语义色 |
| AI 推断 | AI 推测的意图、关系或结论 | “AI 推断”标签 + 置信度/不确定性说明 |
| 待确认 | 尚未获得明确结论的事项 | “待确认”胶囊，需人工处理 |

要求：

- 任何决策与任务默认处于“待确认”，不能因为 AI 输出而自动变为已确认。
- 推断类内容不得使用与事实相同的视觉权重。
- 每条洞察必须展示来源时间范围或片段引用；无来源的推断需明确标注。

### 5.3 洞察区域行为

- 支持折叠、调整宽度、独立展开。
- 洞察按“主题 → 关键观点 → 决策 → 争议 → 待办 → 待确认问题”排序，允许用户固定关注类型。
- 新洞察到达时以轻量提示更新，不整块替换正在阅读的内容。
- AI 分析失败时保留已有结果，显示“分析暂停/重试”，且不影响录音与转录。

## 6. 录音结束后的复盘工作区

录音结束后，不应简单跳转到历史记录列表，而应进入独立的录音复盘工作区。

### 6.1 顶部信息

- 录音标题（可编辑）
- 录音日期与时长
- 参与者 / 说话人
- 音频播放进度与播放控制
- 导出按钮

### 6.2 内容区域

| 区域 | 内容 |
|---|---|
| 录音摘要 | AI 自动总结，标注生成状态 |
| 完整转录 | 全部文字与时间戳，可定位、编辑、复制 |
| 关键观点 | 重要信息与来源 |
| 决策记录 | 已确认的决策，区分“暂定/已确认” |
| 待办事项 | 任务、责任人、截止时间、确认状态 |
| AI 对话 | 对本次录音继续追问，可引用片段 |

布局建议：默认“摘要 + 关键观点 + 决策 + 待办”为阅读主线，完整转录作为独立 Tab 或下半区折叠；不要把所有内容一次性纵向铺开成超长页面。

### 6.3 AI 内容确认流程

录音完成后，AI 生成内容需要经过用户确认才能成为正式记录。

例如 AI 提取任务：

> 完成系统稳定性优化方案。

用户可以选择：**确认 / 编辑 / 忽略**。

要求：

- 未确认内容保留“AI 生成”标识，不计入正式纪要、任务列表或知识库。
- 确认后记录确认人与确认时间（本地单用户场景记录确认时间即可）。
- 编辑后保留原始 AI 输出与修改记录。
- 忽略后不删除来源片段，只从正式记录中隐藏。
- 批量确认需明确列出将被确认的条目，避免误操作。
- 该机制用于避免错误的 AI 结论污染知识库。

### 6.4 导出

- 导出范围应可选：摘要、完整转录、决策、待办、翻译。
- 导出前提示未确认的 AI 内容将如何呈现（排除或标注“未确认”）。
- 复用现有导出能力（WAV、TXT/SRT/VTT、Markdown 纪要等），不重复实现。

## 7. 页面与组件架构

### 7.1 逻辑模块划分

Workspace 应设计为独立业务模块，而不是把所有功能堆在一个页面组件里。建议的逻辑结构：

```text
src/

│   ├── workspace/
│   │   ├── WorkspaceLayout.tsx
│   │   ├── ControlPanel/
│   │   │   ├── RecordingConfig.tsx
│   │   │   ├── AudioDeviceSelector.tsx
│   │   │   ├── AIModelSelector.tsx
│   │   │   └── RecordingController.tsx
│   │   ├── ContentWorkspace/
│   │   │   ├── WorkspaceTabs.tsx
│   │   │   ├── TranscriptView.tsx
│   │   │   ├── TranslationView.tsx
│   │   │   ├── AnalysisView.tsx
│   │   │   ├── TasksView.tsx
│   │   │   └── AIChatView.tsx
│   │   ├── InsightPanel/
│   │   │   ├── TopicCard.tsx
│   │   │   ├── KeyPoints.tsx
│   │   │   ├── Decisions.tsx
│   │   │   └── ActionItems.tsx
│   │   └── Timeline/
│   │       ├── AudioTimeline.tsx
│   │       └── TranscriptSegment.tsx
│   └── history/

├── services/
│   ├── audio/
│   ├── transcription/
│   ├── translation/

└── shared/
```

> 技术栈说明：以上为职责分层参考。当前工程实际为 **Tauri v2 + Vanilla TypeScript**（`apps/desktop/src`），没有 React 运行时。落地时应按同等职责拆分模块与渲染函数，而不是机械引入 React；状态管理、虚拟滚动与持久化方案需结合现有代码评估后确定。

### 7.2 技术选型建议

| 能力 | 建议 | 说明 |
|---|---|---|
| 状态管理 | Zustand 或等价轻量 store | 工作台状态集中管理，避免组件各自推断录音状态 |
| 数据请求与缓存 | TanStack Query 或现有请求层 | 仅在引入相应运行时后采用 |
| 长转录渲染 | React Virtuoso 或等价虚拟列表 | 数百条以上片段必须虚拟化 |
| 波形与电平 | Web Audio API / 后端音频回调 | 具体采集能力取决于桌面运行环境 |
| 持久化 | IndexedDB 或本地文件 | 按运行环境选择；音频分片仍以本地文件为主 |

选型原则：优先复用现有 Tauri 命令、音频分片与历史库能力，不为 UI 重构引入不必要的运行时依赖。

### 7.3 服务边界与并发

- **录音、音频写入、ASR、AI 分析应分别运行**，避免 AI 请求阻塞音频采集。
- AI 服务超时、限流或断网不得导致录音中断或音频分片损坏。
- 转写、翻译、分析使用独立任务队列与取消机制，互不阻塞。
- 前端只订阅状态与增量结果，不在渲染层直接发起长任务。

## 8. 录音工作台的状态设计

这部分容易被忽略，但会直接影响产品稳定性。建议明确以下状态：

| 状态 | UI 表现 | 允许操作 |
|---|---|---|
| Idle | 等待录音，配置可用 | 配置、开始 |
| Initializing | 正在初始化设备与音频管线 | 取消 |
| Recording | 正在录音，计时与波形活动 | 暂停、结束 |
| Paused | 已暂停，波形静止，状态明确 | 恢复、结束 |
| Saving | 正在保存音频与元数据 | 等待（可查看进度） |
| Processing | AI 后处理中，可继续查看已有内容 | 查看进度、取消可取消的任务 |
| Completed | 已完成，可复盘 | 查看、编辑、导出 |
| Error | 发生异常，说明原因 | 恢复、重试、导出已有数据 |

### 8.1 三个关键机制

1. **音频采集与 AI 分析解耦**：AI 服务故障不能导致录音中断。
2. **音频分片持久化**：异常退出后尽量恢复，复用现有 checkpoint 与恢复清单。
3. **保存状态与 AI 处理状态分开**：录音保存成功不意味着 AI 分析也成功，界面必须分别表达。

### 8.2 状态规则

- 保存与 AI 处理是两个独立进度，不能合并为一个“处理中”而隐藏差异。
- 结束录音必须幂等，后端确认前不得重复提交。
- 错误状态必须保留可导出/可恢复的数据，不允许因 AI 失败阻塞录音结果。
- 页面刷新或崩溃恢复后，状态应能从持久化数据重建，而不是依赖内存。

## 10. 最终设计决策与下一步

### 10.1 产品信息架构 V1.0

```text
AI Recording Workspace
├── 录音工作台
│   └── 录音控制 · 实时转录 · AI 洞察
├── 历史录音
│   └── 录音列表 · 搜索 · 回放 · 复盘
├── 知识中心
│   └── 跨录音搜索 · 知识关联 · AI 问答
└── 系统设置
    └── AI 模型 · API Key · 音频 · 数据安全
```

导航层级建议：录音工作台为默认入口；历史录音与复盘共用录音数据模型；知识中心在 V1.0 可只保留入口与占位，不实现跨录音能力。

### 10.2 进入实现前必须锁定的三件事

1. **录音控制面板的宽度、配置层级和状态变化**：三栏还是“控制 + 内容 + 可呼出洞察”，各断点宽度，配置折叠默认值，录音中各状态下的可见项。
2. **实时转录与 AI 洞察的空间关系**：洞察默认宽度、折叠方式、拖拽范围、最小转录宽度，以及新洞察到达时的更新方式。
3. **录音过程中、暂停时、结束后三种主要交互状态**：每屏可见内容、主操作、允许的次要操作、状态文案与错误恢复路径。

### 10.3 下一步交付物

先完成 **Workspace UI V1.0 详细设计规格**，再进入代码实现。详细规格见 [Workspace UI V1.0 详细设计规格](/design/workspace-ui-v1-spec/)。建议规格包含：

- 三栏/断点线框与像素标注（默认 1220 × 900，最小 960 × 640）。
- 左栏配置层级与折叠规则、录音状态区组件规格。
- 五个视图的线框、空态、加载态、错误态。
- 转录片段与 AI 洞察卡片的组件规格、交互状态与来源跳转规则。
- 事实/推断/待确认的视觉标识规范（补充进 [UI 设计规范](/design/ui-guidelines/)）。
- 复盘工作区与确认流程的线框。
- 状态机与关键时序（开始、暂停、结束、保存失败、AI 失败、崩溃恢复）。

### 10.4 待确认项

以下问题需要在详细设计阶段给出结论：

1. V1.0 是否引入说话人分离，还是先用单说话人/顺序编号占位？
2. 翻译默认目标语言与语言对策略；是否支持“仅翻译不转录”？
3. AI 洞察默认展开还是默认收起，取决于目标窗口尺寸与主要使用场景。
4. 双通道电平是否需要在波形上分轨显示，还是一条混合波形加两条电平条？
5. 复盘工作区与历史录音详情是否复用同一套视图，避免两套实现。
6. 知识中心在 V1.0 的占位程度：仅导航入口，还是提供跨录音搜索的只读列表。
